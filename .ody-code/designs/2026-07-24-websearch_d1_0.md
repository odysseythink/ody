# WebSearch 替换 D1.0 架构设计

## 背景与目标

本设计对应 roadmap `.ody-code/roadmaps/2026-07-24-web-search-replacement.md` 的 D1.0 阶段：为 Rust `ody-rs` 中 web search 的彻底替换提供被批准的架构契约。

**目标：** 删除现有 hosted `web_search`、standalone `web/run` 扩展、`alpha/search` 端点、provider/model 能力门控、`web_search_mode` 配置；以 TS `ody-code` 的 `packages/agent-core/src/tools/builtin/web/web-search.ts` 及 `providers/web-search/*` 为唯一参照，重新实现一个 host 可注入 provider、多搜索后端注册表 + fallback、工具名 `WebSearch`、输入参数 `{query, limit, include_content}` 的 web search 工具。

## Architecture / Design

新建 `ody-web-search` crate 作为能力层；app-server 通过 `ExtensionRegistry` 注入 provider；`ody-core` 的 `spec_plan.rs` 将 `WebSearchTool` 视为普通 function tool 注册。

```
Config [services.webSearch]
    → WebSearchProviderRegistry (12 providers)
    → FallbackWebSearchProvider (primary + optional secondary)
    → WebSearchExtension (thread_store injection)
    → WebSearchTool (ToolExecutor<ToolCall>)
    → External Search APIs
```

关键原则：`WebSearchTool` 无 namespace，名 `WebSearch`；未配置 `services.webSearch` 时不注册；输出纯文本；TUI chip 从结构化输出读取计数；`ody-web-search` 不依赖 `ody-api`/`ody-core`，避免循环依赖。

完整架构图、可复用/删除组件清单、流程说明见 `architecture.md`。

## Data Models

核心类型定义于 `ody-web-search`：

```rust
pub struct WebSearchResult { title, url, snippet, date?, content? }
pub struct WebSearchOptions { limit?, include_content?, tool_call_id? }
pub trait WebSearchProvider: Send + Sync { fn name(&self) -> &str; async fn search(...) -> Result<Vec<WebSearchResult>, WebSearchError>; }
pub enum WebSearchProviderName { Duckduckgo, Bing, Serper, ..., Moonshot }
pub struct WebSearchProviderConfig { provider, api_key?, timeout_ms?, options }
pub struct WebSearchConfig { primary, secondary? }
pub struct FallbackWebSearchProvider { primary, secondary? }
pub enum WebSearchError { Network, Timeout, Auth, RateLimited, Provider, Unexpected }
pub struct WebSearchToolOutput { result_count, text }
```

`ConfigToml` 新增 `services: Option<ServicesConfig>`，其中 `web_search: Option<WebSearchConfig>`。

完整类型签名、字段语义、对齐 TS 说明见 `architecture.md` §3。

## Algorithms / Implementation Notes

1. 配置加载：检测到 `web_search` / `tools.web_search` 旧字段立即返回 `ConfigError::Deprecated`；`services.webSearch` 未配置时工具不注册。
2. Thread start：`WebSearchExtension` 解析 `services.webSearch`，用 registry 创建 primary/secondary，包装为 `FallbackWebSearchProvider` 存入 `ExtensionData`。
3. Tool contributor：存在 provider 状态时返回 `Arc::new(WebSearchTool::new(provider))`。
4. Tool execution：解析 `{ query, limit?, include_content? }`；调用 `FallbackWebSearchProvider.search`；构造 `WebSearchToolOutput { result_count: results.len(), text }`；空结果 `text = "No search results found."`。
5. TUI chip：从 `WebSearchToolOutput.result_count` 读取计数，显示 `N results` / `1 result` / `no results`。

完整伪代码、schema 定义、注入代码见 `config-tool-tui.md` §1–§4。

## Error Handling / Degradation

- Provider 内部将 HTTP/reqwest 错误分类为 `WebSearchError`（Network/Timeout/Auth/RateLimited/Provider/Unexpected）。
- `FallbackWebSearchProvider` 仅在 primary 失败时切换 secondary，不重试、不合并、不降级为空结果 `[C:USER]`。
- `WebSearchTool` 将 `WebSearchError` 包装为 `FunctionCallError::Fatal(error.user_message())`；`user_message()` 返回面向用户的通用文本（如 `"Search temporarily unavailable."`），分类前缀仅在结构化日志/tracing 中保留，不传递给模型。
- 空结果不是错误，返回 `"No search results found."`。
- 旧 `WebSearchItem`/`WebSearchAction`/`WebSearchBegin`/`WebSearchEnd` 协议字段：保留类型的 `#[serde(default)]` 兼容反序列化，旧历史加载时降级为普通文本消息或丢弃，不 panic。

完整错误分类表、HTTP 状态码映射、边界行为表见 `providers.md` §4–§5；旧历史兼容方案见 `config-tool-tui.md` §6。

## Self-Review

### 最贵重的 1–3 个决策

1. **新建 `ody-web-search` crate 的依赖边界** — 错误会导致 workspace 循环依赖。
2. **旧协议字段完全删除 vs. 保留兼容层** — 错误会影响用户升级体验。
3. **`services.webSearch` 未配置时工具完全不注册** — 错误会产生大量 support burden。

### 四镜头审查

- **Security**：API key 明文配置改为支持 env var 回退；配置打印/日志必须 mask key；错误消息不再暴露内部分类前缀给模型。
- **Test/Verification**：测试覆盖 provider、registry/fallback、config、tool、parity；增加可选 `#[ignore]` contract tests 验证真实 API。
- **Operations**：旧配置严格迁移，需在 changelog 中突出说明；第一批 provider 改为 Bing/SerpApi/SearchApi/Moonshot。
- **Integration**：extension 注入模式与现有 MCP/skills 扩展一致；`ody-web-search` 不依赖 `ody-api`/`ody-core`，避免循环依赖；旧协议字段保留兼容反序列化。

### Scope 重检

与 roadmap D1.0 一致；OAuth、hosted tool、OpenPage/FindInPage 已明确排除。根据 adversarial review 调整：DuckDuckGo 移至第二批；错误消息对模型通用化；增加 env var key 回退；TUI chip 改为结构化计数；增加 options whitelist 校验；增加旧协议字段兼容反序列化。
