# 人工验收工作台（首版）

Default 模式的主会话提供 `human_acceptance` 工具。模型仅在主观体验、实体设备、无法访问的外部环境等确实需要人工时使用，不应把自动化测试失败直接转交用户。

## 使用流程

TUI 快捷入口：开发完成后输入 `/acceptance`。在 Default 模式的主会话中，命令让模型先用 `human_acceptance(action=list)` 查找本工作目录/会话未提交的验收（最近修改优先，最多返回 20 个），优先重开最近一轮；没有待验收时根据当前开发上下文生成详细用例并打开页面。上下文不足时先澄清，不编造用例。命令只授权创建/重开验收数据，不授权修改项目代码，也不自动切换模式。提交后仍自动通知原会话。该入口需要模型调用工具，并非绕过模型直接打开网页。

1. `action: "create"`，传入 `plan`：标题、用例列表，每项包含唯一 `id`、`title`、人工原因 `reason`、前置条件 `prerequisites`、`steps`（每步 `action` 与 `expected`）。自动打开默认浏览器；失败时提供 URL 手动打开。
2. 用户按步骤操作，选择通过、不通过或无法执行。不通过/无法执行必须解释实际现象；支持填写证据引用，首版不上传附件。切换用例会保存，关闭页面前应点击保存。
3. 所有用例反馈后提交，本轮变为只读。结果先落盘，再自动通知原会话；用户不必再发送“验收完成”。模型用 `action: "get", run_id` 读取结果摘要，再加 `case_id` 读取具体反馈，避免大批用例挤占上下文。不通过/无法执行必须读取实际反馈再处理。未提交、无法执行都不能算通过。
4. 修复后再次 `create`，设置 `plan.previous_run` 关联原轮次，保留历史。
5. 重启后在原工作目录、原会话用 `action: "open", run_id` 重开；旧 URL 失效，新访问凭证自动生成。

数据保存在 `.ody-code/acceptance/<thread-id>/<run-id>.json`，创建/重开检查当前环境的写权限，只支持本地工作目录。不要将含敏感反馈的数据提交进版本控制。建议项目忽略 `.ody-code/acceptance/`。

## 自动通知

- 提交成功后，`notification` 为 `queued` 表示原会话已收到信号，页面提示无需再发送消息；不表示模型已分析完。
- 空闲且处于 Default 模式时自动启动新轮次。忙碌时不替换当前任务，信号按现有输入交付阶段消费，或在任务结束后启动轮次。Plan/Design/Product 模式不因验收信号自动启动新轮次。
- 通知只携带验收 UUID，不把自由文本反馈作为执行指令。原会话继续遵守既有任务授权，演示验收不会额外授权修改代码。
- `pending` 表示结果已保存但通知尚未确认。页面提供“重试通知”，重开待通知任务也会自动重试。重复/并发重试通过持久化状态和会话内验收 ID 去重。
- 关闭原会话会停止它的站点并关闭通知队列。连接使用弱引用，不让站点延长原会话生命周期。
- 队列是当前进程内存队列；确认 `queued` 后若进程在消费通知前崩溃，不保证自动恢复该信号。结果仍在磁盘，可在恢复原会话后主动让模型读取。没有跨进程常驻服务、自动重启会话或后台轮询。

## 安全与边界

- 仅监听 `127.0.0.1` 随机端口。API 验证随机 Bearer 凭证、Host 和 Origin；凭证使用 URL fragment，不进入 HTTP 请求 URL。无跨域放行。
- 完整 URL 含访问凭证，不要转发或贴到公共日志；重开会撤销旧站点的访问凭证。
- 模型和用户内容只按纯文本渲染，页面无命令执行接口。CSP 禁止外部脚本和嵌入，响应禁用缓存和 referrer。
- 原子保存、revision 冲突检测、输入大小限制、线程归属校验、提交后不可变、拒绝符号链接存储路径。
- 最多保留 16 个站点监听器；重开同一轮关闭旧监听器。进程退出停止服务，数据不丢失。
- 尚无桌面专用嵌入、附件上传、测试命令自动执行。自动通知连接未配置时（例如独立使用库），页面仍提示用户手动返回会话。
- 站点获得开启时的写授权并持续服务至重开、监听器淘汰或进程退出；尚未对后续权限配置变更做动态撤销。仅面向本机受信任使用，不是多用户服务；不防御恶意本地进程对文件的并发替换。

验证：`cargo nextest run -p ody-human-acceptance`；前端交互契约 `node --test human-acceptance/tests/ui.test.cjs`；工具接入验证 `cargo check -p ody-core` 和 `cargo nextest run -p ody-core --lib -E 'test(human_acceptance_is_only_exposed)'`。前端契约测试不替代真实浏览器验收。

自动通知回归：`cargo nextest run -p ody-core --lib -E 'test(human_acceptance::tests::) | test(host_notifications_) | test(input_queue::tests::) | test(try_start_turn_if_idle_)'`。

快捷入口回归：`cargo nextest run -p ody-tui --lib -E 'test(acceptance_shortcut)'`。人工验证时，在已有开发/用例上下文的 Default 主会话输入 `/acceptance`，确认页面打开；未提交时再次输入应重开同一 `run_id`；提交后原会话自动汇总。模式限制、权限与浏览器打开失败时的链接回退仍遵守上述规则。

手动验证：重新编译 `cargo build -p ody-cli`，在 `./target/debug/ody` 的 Default 主会话创建一轮人工验收（可明确要求“仅演示，不修改代码”）；在页面完成并提交后，不发送任何会话消息，直接观察原会话是否自动读取和汇总结果。重复重试/重开已通知任务不应重复唤醒。
